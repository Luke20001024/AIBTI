## 2. 统一后的结果页叙事结构

所有人格固定为六段，目的不是让页面长得一模一样，而是让用户不用重新学习阅读方式

1. **人格首屏**：一张完整海报同时交付人格代码、人格名、两行判断、三个关键词、角色和空间场景
2. **先说人话**：用两到三段短文直接说清用户如何看空间、喜欢什么、容易踩什么坑
3. **代表建筑师**：一句有网感的开场 + 方法说明 + 风格化人物插画；完整经历收进人物档案
4. **三次实锤**：三座主作品连续展示，每座用真实建筑图、一个明确判断和一个档案入口完成证明
5. **继续看**：再补两座同一建筑师作品；其他相近建筑师只用一行带过，不再抢主叙事
6. **结果收口**：一句人格结论、三个情绪关键词、保存人格卡、分享、重测和来源入口

这套结构把“为什么是这个人格 → 谁把它建出来 → 建筑里到底看什么”压缩为一条连续路径，解决旧稿中“空间本能、三层结构、建筑师”之间跳转过慢的问题

## 3. 本轮系统性修复

### 3.1 内容与事实

- 16 页每页均为 1 位代表建筑师或 1 组真实合作建筑师 + 5 座其本人/团队的作品
- 其他建筑师只在“同频参考”中以一行文本出现，不再把他人的建筑误放进代表建筑师作品区
- 80 个建筑档案全部使用真实建筑照片，不使用 AI 生成的具体作品冒充实景
- 80 个建筑档案全部配置 2–3 张可靠照片；最后一轮为原先 19 个单图项目逐项补图并人工复核，没有使用重复、规划扫描或错误建筑凑数
- 16 个人物档案统一使用风格化、低多边形或编辑插画式肖像；双人组合保留完整双人构图，不再被 HTML 裁掉其中一人
- 对正文中的“不是 / 而是 / 别抄 / 抄这个”进行系统重写；最终结果页数据回归为 0 处重复对照脚手架
- “补充判断”改为小字斜体句，不再使用带边框、色条和标题的强调模块

### 3.2 UI 与阅读

- 主题背景统一提亮，以低饱和浅色区分人格，避免深底导致大段正文发闷
- 正文维持手机杂志式紧凑行距；不通过大行距制造“高级感”
- 章节标题收小，避免标题占据整屏；内容层级由字号、字重、留白和图文比例共同完成
- 移除大量横线切割，分段优先使用自然留白和背景轻微变化
- 外层主页面保持直白、可扫读；更多图片、经历、现场观察和来源放入全高 Sheet
- 主作品图片不再做两列超窄裁切；外层完整呈现，档案内按一张主图 + 续图自然向下阅读
- 图片完整显示规则从首屏扩展到整站内容媒体：人物肖像、三座主作品、两座延伸作品、档案主图、档案图组、16 人格目录和图像题全部取消固定高度、固定宽高比与 `cover` 裁切；容器随图片固有比例生长
- 内容图片统一带有 `data-media-fit="intrinsic"`，浏览器回归会逐张比较渲染比例与天然比例，避免后续换图或改尺寸时再次出现“下半截消失”
- 结尾保存/分享按钮修复等宽与容器边界，不再发生左侧按钮溢出或遮挡
- 16 张人格首屏取消固定视口高度与 `cover` 裁切；容器跟随海报固有比例，图片始终等比铺满内容宽度，在不同页面高度下完整显示且没有左右留白
- 16 张人格首屏和后 8 张高分辨率建筑师插画增加同尺寸 WebP 展示资产，24 张核心移动图从约 45.2 MB 降至约 4.0 MB，减小 91.2%；PNG 人格原稿继续用于保存和社交预览
- 旧版 Safari 对 `dvh`、`svh`、`color-mix()` 和 `overflow: clip` 不完整支持时，页面会回退到 `vh`、静态浅色底和 `overflow: hidden`

### 3.3 交互

- 每页 1 个人物档案 + 5 个建筑档案，共 6 个内容 Sheet
- Sheet 打开时锁定背景滚动，关闭后恢复原位置
- 每个档案都有明确标题、完整图片替代文本、现场观察、方法解释和资料来源入口
- 页面不再依赖箭头教学、逐步点击提示或无意义动效；交互只在用户希望深入时出现
- 所有结果页的“重新测试”会同时删除本地与会话存储中的答题进度、动态追问和本地结果，再从第 1 题开始；`reset=1` 提供进入题页后的第二层清理保障
