# ArcBTI 题目与评分 V4 实施及测试计划

## 目标

保持手机端约三分钟的完成节奏，同时让 16 种人格都能被真实区分。核心题固定为 18 道；只有头两名过近或落入已知碰撞组时，才追加 1–2 道「最后判断」

## 题目结构

- Q01–Q06：空间本能，组权重 0.30
- Q07–Q12：空间价值，组权重 0.35
- Q13–Q18：建筑直觉，组权重 0.35
- T01–T08：动态辨析池，每次只调用最相关的题，最多两道

八组重点碰撞：ROOT/HAND、MASS/TECH、VOID/RUIN、ORNA/SIGN、ROOT/EAVE/TIDE、TECH/SPAN、HAND/PLUS、FLOW/MIX/VEIL

## 动态规则

1. 完成 18 道核心题后先计算头两名差距
2. 已知碰撞组直接调用对应辨析题；普通近似结果按向量分离度选择最有效题
3. 首次差距小于 0.14 或命中碰撞组时追加第一题
4. 第一题后差距仍小于 0.055 时追加第二题
5. 两道动态题合计影响上限为每个维度 0.12，禁止反客为主
6. 动态答案独立编码在 URL fragment 的 `d` 字段，结果 URL 不保留核心或动态答案

## 文案规则

- 每个选项先给具体动作，不写抽象人格结论
- 单句能说清时不拆分点
- 去掉句末句号
- 减少「不是……而是……」和绕弯定义
- 保留轻微幽默，但不让梗盖过建筑判断

## 自动测试

- 18 道核心题数量、三组平衡和每题三选项合同
- 8 道辨析题唯一性、选项合法性和文案句末规则
- 已知碰撞优先选择专用题
- 动态题最多两道
- 动态层每维影响不超过 0.12
- 10 万组固定随机样本覆盖全部 16 人格
- 核心答案与动态答案的编码、解析、重复值、非法值和版本错误
- 本地进度只保留当前题目序列需要的动态答案
- 题目、结果、建筑师、作品与可见图片关系完整

## 手机端闭环测试

在 iPhone 390×844、Android 393×873、HarmonyOS 代理 390×844 完整跑一次：清空本地数据 → 完成 18 道核心题 → 至少出现 1 道最后判断 → 最多出现 2 道 → 计算页 → 结果页 → 本地结果版本为 4.0.0 → 结果 URL 不含 `a/d/q/s/u`

## 验收门槛

- 单元测试 100% 通过
- 16 人格全部可达且任何单一人格样本占比不低于 1.8%
- 手机 E2E 无横向溢出、无破图、无动态题死循环
- 页面刷新后能恢复当前题；修改核心答案会清掉旧的动态答案
- 旧版本本地进度不被误解释为 V4
