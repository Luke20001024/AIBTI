### A1 产品北极星与完成定义

ArcBTI 3.0 的产品北极星：

> 让用户辨认自己天然读得懂哪一种建筑语言，并通过一位代表建筑师和真实作品把这种直觉变成可记忆、可学习、可分享的建筑身份

用户完成测试后，必须能够自然复述：

> 我的建筑母语是诗意留白，代表建筑师是安藤忠雄，代表建筑是光之教堂

完成定义：

- 首页、18 题、计算、Owner 结果、Shared 结果、详情资料卡、分享卡与重测形成完整手机闭环
- 用户进入结果页三秒内看到建筑语言、代表建筑师和代表建筑
- 结果页无需打开详情卡也能完成身份认领，打开资料卡后又能获得完整建筑科普
- 用户能够从三条真实答案证据理解结果来源，不依赖传统人格套话
- 三座核心建筑提供足够大的预览图，详情卡提供三至五张图片与观看提示
- 公开结果不包含用户答案；Owner 个性化证据仅保存在本机
- 八种结果都能用一句“建筑母语 + 建筑师 + 建筑”的格式传播
- 题目选项不存在明显无人选择的弱项，视觉题不依赖建筑专业知识
- iPhone、Android、微信内置浏览器与 HarmonyOS 末题完成链路保持可用
- 本地候选通过视觉保真、功能、构建和自动设备矩阵后，才允许提交与部署

### A2 双层身份模型

ArcBTI 3.0 将结果拆成四个相互关联但职责不同的层级：

| 层级 | 回答的问题 | 用户可见形式 | 是否用于分享 |
|---|---|---|---|
| ArcBTI 人格代码 | 我属于哪种结果类型 | `VOID`、`ROOT` 等四字母代码 | 是，作为品牌识别 |
| 建筑母语 | 我天然读得懂哪种建筑语言 | 诗意留白、理性秩序等 | 是，作为主结论 |
| 建筑谱系 | 这种语言与哪些真实学派和历史脉络相关 | 学派资料卡 | 否，作为科普层 |
| 建筑锚点 | 谁与哪座建筑最能把这种语言讲清楚 | 代表建筑师 + 代表建筑 | 是，作为记忆锚点 |

ArcBTI 归纳标签不得冒充正式学派
“清水混凝土”属于材料与表达方式，不得独立写成建筑学派
“代表建筑师”表示该类型的主要知识入口，不表示用户与建筑师具有相同人格，也不表示心理学诊断

#### A5.8 VOID 建筑作品资料卡模板

以光之教堂为样板：

```text
光之教堂
Church of the Light

日本大阪 · 1989
安藤忠雄

一句话理解
墙面几乎什么都没有，光本身成为空间中最强烈的构件

关键动作
一面斜墙先改变进入路线
十字开口把室外光直接带到会众面前
极少材料放大每天不同的明暗变化

应该看哪里
先看人如何绕过墙进入
再看十字光与座位方向的关系
最后看混凝土表面怎样让光变得可见

为什么属于 VOID
它不靠增加形式制造情绪，而是通过减少材料，让光、路径和停顿变得更强
```

正式卡片需要三至五张图片：

- 一张建筑或入口环境
- 一张室内十字光
- 一张路径或斜墙关系
- 一张材料与光线细部
- 可选一张平面或可公开使用的说明图

### A6 18 题重构合同

#### A6.1 三幕结构

| 题号 | 分组 | 主要测量 | 结果职责 |
|---|---|---|---|
| 01—06 | 空间本能 | 光、边界、距离、路径、停留与场所直觉 | 为结果证据和人格气质提供材料 |
| 07—12 | 空间价值 | 用户认为好空间首先应保护什么 | 决定建筑母语的主要方向 |
| 13—18 | 视觉直觉 | 窗、边界、结构、材料、路径与公共距离 | 直接校准建筑语言与作品观看偏好 |

#### A6.2 单题权重规则

- 每题只有一个主维度和最多一个修正维度
- 每个选项的权重数量、强度和语义粒度相近
- 每个选项至少支持两种结果，不允许成为某一人格名称的直译
- 题目不要求用户知道建筑师、学派或专业术语
- 三个选项都必须具有合理吸引力，不设置成熟／幼稚、善良／冷漠、专业／愚蠢的隐性高低
- 用户应能在五秒内说出三个选项的区别
- 每个选项必须配置人工证据文案，评分不再直接拼接维度名称
- 三组权重和四条核心建筑轴的最终数值必须经过模拟后再锁定，不在内容写作阶段凭感觉填写

#### A6.3 核心建筑轴与修正倾向

建筑母语使用四条核心轴：

- 规整秩序 ↔ 自发生长
- 克制留白 ↔ 强烈表达
- 内聚庇护 ↔ 公共开放
- 抽象新造 ↔ 场所时间

建筑师与结果解释使用三个修正倾向：

- 稳健 ↔ 冒险
- 独处 ↔ 协作
- 系统控制 ↔ 材料试作

八种结果继续使用向量中心匹配，不改成四组简单二选一
本版本每型仍固定一位代表建筑师，修正倾向只用于证据与人物解释，不动态生成二十多种建筑师组合

#### A6.5 第一轮平衡审查

每道题在写入代码前必须完成以下检查：

- 把 A／B／C 顺序打乱后，审查者仍能理解三项区别
- 隐去题号和分组后，审查者不能直接猜出某个选项对应的具体人格代码
- 三项不存在明显更完整、更成熟、更温暖或更有道德优势的表述
- 三项字数差距原则上不超过约 40%，必要差异必须来自语义而不是文案偷懒
- 三项动词强度相近，不用“只能”“不过”“勉强”等词故意削弱某项
- 视觉题的三张图主体面积、透视、光线、饱和度、人物数量和背景复杂度接近
- 每项至少能形成一条自然证据文案，而不是只能翻译成底层维度名
- 每个结果至少在六道以上题目中获得明确支持，不能只依赖一两道标志性题
- GRID／MASS／TECH 和 ROOT／HAND 的近邻区分必须分别有至少两道有效题
- VOID 与 GRID 不得仅靠“内向”区分，FLOW 与 ORNA 不得仅靠“夸张”区分

#### A6.6 人工证据文案样例

每个选项在内容层配置一句可以独立出现在结果页的解释
以下先以 Q01、Q02 和 Q06 验证语言口径：

| 题目选项 | 不允许的自动解释 | 正式证据文案方向 |
|---|---|---|
| Q01 A 把声音轻轻压低 | 你选择了内聚与克制 | 进入陌生空间时，你先寻找能让感官安静下来的边界 |
| Q01 B 把去向一眼讲清 | 你选择了秩序与系统 | 你希望空间先把路线说明白，再谈情绪 |
| Q01 C 让视线一直跑到远处 | 你选择了开放与表达 | 你容易被没有视觉阻挡的空间吸引 |
| Q02 A 干净到看不出年代的墙 | 你选择了抽象新造 | 你欣赏脱离具体年代、只留下比例和表面的空间 |
| Q02 B 让光每天换位置的墙 | 你选择了时间 | 你愿意让一天中的光线替空间持续改写表情 |
| Q02 C 保留修补痕迹的旧墙 | 你选择了场所时间 | 你不会急着抹掉材料已经经历过的时间 |
| Q06 A 量好尺寸，接进现有系统 | 你选择了系统控制 | 面对陌生材料时，你先确认它如何进入一套可理解的结构 |
| Q06 B 直接动手，看它会变成什么 | 你选择了材料试作 | 你更相信试作中的反馈，而不是一开始就把结果锁死 |
| Q06 C 先找它以前属于哪里 | 你选择了场所与记忆 | 在决定材料的新用途前，你会先追问它来自哪里 |

证据正文不得使用“最明显地指向”“说明你是”“证明你具有”等诊断口吻

### A7 后六道真实生成题图合同

后六题的最终资产使用真实图像生成，不再以代码原生 SVG 为交付
图像风格必须与当前 `characters-v3` 人格角色处于同一视觉世界：成人角色审美、低多边形／切纸几何语言、克制的建筑背景、明确的空间层次、有限的 ArcBTI 蓝色强调与不过度戏剧化的光线
题图不必出现人物；如果出现人物，只能作为尺度参照，不得成为选项吸引力中心

每道题的生产方式：

1. 先生成一张包含三个等分场景的纵向母图，三格使用同一基础空间、同一观察角度、同一时刻和相近画面密度
2. 三个场景只改变该题测量的一个空间变量
3. 不在生成图中写 A／B／C、题号、选项文字、品牌名或说明文字
4. 先对母图做盲审，确认三个选项没有明显的画质、亮度、构图和戏剧性优势
5. 将通过的母图裁成三张相同尺寸的独立资产
6. 统一压缩为 WebP，保留高分辨率母图作为设计源文件
7. 页面文字、选项编号、选中边框与交互全部由 HTML／CSS 输出

六道视觉变量：

| 题号 | 视觉变量 | 三选项必须保持不变 | 只允许改变 |
|---|---|---|---|
| 13 | 空间体量 | 场地、相机、天气、尺度参照 | 稳定体量／连续曲面／装配骨架 |
| 14 | 空间氛围 | 房间尺寸、视点、人物数量 | 聚光内省／自然庭院／装饰包围 |
| 15 | 材料触感 | 墙体构图、光线方向、取景距离 | 旧砖／模板混凝土／精密金属 |
| 16 | 窗与观看 | 同一房间、同一景观、同一家具 | 水平长窗／框景小窗／整面巨窗 |
| 17 | 公共空间 | 同一城市地块、同一人流数量 | 修补路径／连续地景／可升级骨架 |
| 18 | 时间与不完美 | 同一构件、同一尺度、同一环境 | 秩序留空／材料风化／未来悬曲面 |

最终网页资产建议规格：

- 每张统一为 3:2 或经概念确认后的同一横向比例
- 每张有效像素不少于约 900 × 600
- 单张 WebP 目标约 60KB 至 120KB
- 每题三张图总体目标不超过约 360KB
- 当前题只加载本题图片，可预取下一题，不在首页预载全部 18 张
- 360px 至 430px 手机宽度下图片不能出现大量无意义空白
- 三个选项的主体尺寸、亮度、饱和度、细节量和视觉重心必须接近
- 题图审查总览必须同时展示六道母图、18 张裁切图和真实手机卡片截图

### A8 移动端资料卡合同

统一组件 `ResultDetailSheet` 承载学派、建筑师、建筑作品与方法来源
视觉上是一张从底部升起的资料卡，功能上接近独立移动页面

必须满足：

- 高度约为视口的 88% 至 94%
- 顶部标题和关闭按钮始终可达
- 内容自然纵向滚动，不嵌套第二层弹窗

#### V2.1.1 执行摘要

#### V2.1.4 根因判断

1. **完成定义偏差**：后续 Agent 接收到的是功能和资产数量清单，不是用户体验结果
2. **PRD 优先级不足**：旧 PRD 内容完整，但缺少位于最前面的短执行合同，Agent 需要自行从大量章节推断当前重点
3. **缺少黄金样板**：没有先用少量题目、页面和三种情绪人物确定统一标准，再进入全量制作
4. **素材与页面分离验收**：人物图以原图完成度验收，没有同时放进首页、结果页和分享卡进行真实手机验证
5. **批量生产过早**：八张人物与完整内容较早进入批量制作，后期只能局部修补，难以调整整体语言
6. **内容缺少行为校准**：题目有创意，但未经过选项选择率、结果分布、映射泄露和用户理解测试
7. **QA 重功能轻感知**：兼容和部署有清晰通过条件，认同感、美感、图像可读性和传播力缺少同等级闸门

### V2.2 执行目标、非目标与优先级

#### V2.2.1 V2 执行目标

在保留 v1 稳定技术底座和建筑资料库的前提下，完成一版面向 iPhone、Android 与 HarmonyOS 手机浏览器的 AIBTI V2，使用户能够通过选择相对平衡、直观而有趣的题目获得可信且有认同感的建筑人格结果；八类角色具有统一的品牌视觉和明显不同的性格演出；结果首屏与分享卡能够独立形成传播；完成全链路、三平台和线上 GitHub Pages 验收

产品设计与真实使用体验高于对 v1 版式和视觉资产的继承。只要保留已经验证的产品价值、人格与建筑资料关系、稳定计分能力和可回退技术基线，后续 Agent 可以重组信息架构、页面节奏、视觉层级、交互方式和媒体构图；不得因为“旧版已经实现”而保留明显不符合 V2 目标的设计

#### V2.2.2 最高优先级

发生冲突时，后续 Agent 必须按以下顺序决策：

1. 手机端可理解、可操作和完整闭环
2. 题目选择平衡与结果认同感
3. 人物与页面的视觉一致性
4. 分享卡的身份表达与传播力
5. 建筑科普的可信度与编辑体验
6. 内容数量和新功能

#### V2.2.3 本轮非目标

- 不做竞品研究
- 不重新命名品牌或更换域名
- 不增加人格和题目；建筑资料以当前 40 座为本轮上限，不继续扩容
- 不增加登录、后端、CMS、排行榜和好友功能
- 不因为重构而更换 Next.js、GitHub Pages 或客户端计分方案
- 不把“高级感”理解为增加阴影、渐变、玻璃卡片、过度圆角或大片留白
- 不为了赶时间绕过样板闸门直接批量生成八张新人物图

#### V2.2.4 V2 完成定义

只有同时满足以下条件，才能将 V2 标记为完成：

- 18 道题均完成内容平衡检查，计分回归测试通过
- 后六题图像在手机尺寸下可以快速区分，不依赖专业术语猜测
- 八类人物属于同一视觉系统，同时覆盖克制、温和、安静、固执、兴奋、戏剧和癫狂等不同状态

- 结果首屏能够在短时间内说明“我是谁、为什么像我、与哪位建筑师和哪类建筑同频”
- 分享卡在聊天缩略图和全屏预览中均能识别人格代码、人格名与人物

### V2.9 产品北极星与身份形成顺序

#### V2.9.1 北极星

V2 的核心不是让用户读完一份更完整的建筑报告，而是让身份认同自然把用户带进建筑知识

> 用户在首页 8 秒内理解玩法，在测试中持续凭直觉作答，在结果出现后 20 秒内感到“有点像我”，在 60 秒内看懂至少一座建筑，并愿意把人格卡发给朋友

以下顺序是产品结构，不得被旧页面实现覆盖：

```text
被勾起好奇
  → 凭直觉选择
  → 身份揭晓
  → 看见三个来自本人答案的证据
  → 认领并分享身份
  → 在日常行为中进一步认出自己
  → 连接到一位真实建筑师的故事
  → 真正看懂一座主建筑
  → 决定是否继续探索另外两座
```

v1 的“标准人格长文 → 八维图 → 证据题 → 分享 → 建筑师 → 三座等长建筑”顺序停止沿用

#### V2.9.2 页面与每屏唯一任务

| 屏幕 | 唯一任务 | 首层必须出现 | 首层不得出现 |
|---|---|---|---|
| H0 首页 | 理解玩法并开始或继续 | 品牌、价值句、性格跨度视觉、主按钮、18 题／3 分钟／免登录 | 大段方法论、完整人格列表、单一冷酷角色代表全站 |
| Q-T 文字题 | 凭第一反应选一个答案 | 流程微标、进度、题目、三个等权选项、返回 | 全站导航、方法与图源入口、重复题号 |
| Q-V 图像题 | 看懂三个空间差异并选择 | 等尺寸图像、短标签、清楚选中反馈 | 抽象渐变、只靠颜色判断、缩小到不可读的建筑图 |
| Q-18 最后一题 | 完成最后选择并主动揭晓 | 最后一道提示、选择、`查看我的建筑人格` | 只依赖延迟自动跳转 |
| C0 计算页 | 制造约一秒期待并保证进入结果 | 一条揭晓文案、隐私提示、超时备用入口 | 伪装长时间科学计算、连续多段干扰文案 |
| R0 结果揭晓 | 看清“我是谁” | 代码、名称、台词、人物和主建筑、同频对象 | 制作术语、八维数据、来源长列表 |
| R1 个性化证据 | 相信“为什么是我” | 三个选择、每个选择暴露的倾向、共同指向 | 只显示题干、不显示本人选项 |
| R2 身份认领 | 保存或传播已经相信的身份 | 分享卡动作、公开链接动作、隐私说明 | 相邻人格、原始答案、操作型卡面文案 |
| R3 人格剖面 | 在日常行为中继续认出自己 | 现实、潜意识、压力反应、三个最强倾向 | 默认展开全部八维仪表盘 |
| R4 建筑师桥梁 | 把人格连接到真实人物 | 一位／组代表建筑师、一个好记的故事 | 先用免责声明和来源打断情绪 |
| R5 主建筑 | 真正看懂一座建筑 | 一张好图、Hook、三个看点、一个故事 | 三座建筑等长并列 |
| R6 延伸建筑 | 决定是否继续探索 | 另外两座的图、名称、短 Hook | 重复完整长文与完整来源 |
| R7 尾页 | 重测、看相邻人格或理解方法 | 三个明确出口 | 无返回测试动作的资料死路 |
| S0 分享态 | 看懂朋友的结果并开始自己的测试 | `朋友测出了`、人格、主 CTA | `你的建筑人格`、朋友答案和八维 |
| SP 分享预览 | 保存图片或转发 | 分享卡、系统分享、保存、复制测试链接 | 相邻人格和答案短码 |
| A0 About | 建立信任并回到体验 | 算法边界、隐私、来源、开始测试 | 一进入就铺满来源索引 |

#### V2.9.3 测试三幕节奏

内部仍保留 6 道潜意识、6 道日常人格、6 道建筑直觉及其组权重，但题面不按 6＋6＋6 连续暴露模型，改为混排的三幕体验：

1. **先拆掉理性**：从最易想象、最想立即选择的问题开始，混入一至两道直观图像题
2. **看看你平时怎么建**：用均有优势和代价的日常选择建立人格识别，避免连续重复同一三分法
3. **只剩建筑直觉**：材料、开口、光线、体量和场所形成视觉高潮，最后一题必须是全套最清楚、最愿意作答的一题

首题只提示一次：

```text
凭第一反应
没有正确答案
```

### V2.10 Owner／Shared／Explore 状态与隐私边界

#### V2.10.1 三种结果状态

| 状态 | 进入条件 | 个性化内容 | 主动作 |
|---|---|---|---|
| Owner 本人 | URL 请求本人模式，且本机存在类型和版本均匹配的有效结果 | 三个证据、三个倾向、副类型、完整八维 | 认领分享、继续阅读 |
| Shared 朋友分享 | `from=share` 或 `from=card`，或 `mine=1` 但本机无匹配结果 | 只显示公共人格、建筑师和建筑 | 测测我是哪一种 |
| Explore 中性浏览 | 无本人和分享标记，或从站内人格索引进入 | 公共人格、建筑师和建筑 | 开始测试 |

状态解析优先级已经锁定：显式 `from=share` 或 `from=card` 高于本机 Owner 数据，裸结果路由始终是 Explore；`mine=1` 不能单独证明 Owner 身份，本机结果缺失、过期、类型不匹配或任一版本不匹配时必须安全降级为 Shared，不得展示零值八维或伪造个性化证据

#### V2.10.2 URL 口径

以 ROOT 为例：

```text
本人结果      /result/root/?mine=1
公开分享      /result/root/?from=share
分享卡入口    /result/root/?from=card
中性资料      /result/root/
```

- 复制链接与系统分享使用 `?from=share`，分享卡二维码使用 `?from=card`，均为公开类型入口
- V2 默认公开 URL 不包含原始答案短码
- Owner 个性化数据保留在同设备浏览器中
- v1 带 `a`、`q`、`s` 或 `u` 的旧链接只标记为旧版，不解码、不迁移，也不得用 V2 题序重新解释；最小降级为对应人格的 Shared 或 Explore 页面
- 无后端条件下不承诺跨设备恢复本人证据、动态个人 OG、好友关系或服务端隐私控制

#### V2.10.3 本地版本策略

V2 必须新建版本化存储，不能继续复用 `aibti.quiz.v1`：

```text
aibti.quiz.v2
aibti.result.v2
```

本地结果至少保存：

```ts
type LocalResultV2 = {
  schemaVersion: 2
  quizVersion: string
  scoringVersion: string
  contentVersion: string
  artVersion: string
  primaryTypeId: string
  secondaryTypeId: string
  confidence: number
  clarity: "clear" | "balanced" | "mixed"
  gap: number
  dimensionScores: Record<string, number>
  evidence: Array<{
    questionId: string
    optionId: string
    choiceLabel: string
    interpretation: string
  }>
  completedAt: string
}
```

结果优先写入 `localStorage`，受限内嵌浏览器拒绝写入时降级到同标签页的 `sessionStorage`；两个存储都不可用时仍完成计分，但只进入不含个性化证据的 Shared 页面

进度恢复时必须同时验证 schema、题库版本、完整题目 ID 顺序和选项 ID；Owner 结果还必须验证题库、计分、内容、美术版本与当前结果类型，V1 数据只读，不原地迁移为 V2 答案

### V2.11 已锁定的视觉方向与设计系统

#### V2.11.1 视觉命题

> 一份会突然活起来的建筑编辑现场手册

它由四个层次组成：

- 建筑编辑感：强标题、清楚网格、1px 线、真实资料、图像说明
- 人格游戏感：直接问题、反差台词、角色表情和动作、揭晓仪式
- 手机内容密度：相关内容聚在一个视口内，媒体主动铺满，不用空白伪装高级
- UI 克制：界面退后，人物、建筑和文字承担表达，不靠组件装饰建立风格

#### V2.11.2 第一轮概念锚点

概念图不是可任意降级的气氛参考。除用户明确覆盖的页面外，它们是字号张力、内容密度、图像面积、选中态和编辑节奏的硬性视觉基线；实现截图必须逐项对照，不得只保留信息结构后重建成通用模板

| 场景 | 参考文件 | 已锁定内容 | 待真实页面验证 |
|---|---|---|---|
| 首页 | 用户 2026-08-26 最新覆盖口径 | 纯文字封面，只保留品牌、超大标题、单句说明、主按钮和事实行；首页不出现人物图 | 390 × 844 首屏完成理解与行动，无无意义空白 |
| 文字题 | `docs/design/v2/concepts/quiz-text-v1.webp` | 三个大面积等权选项、左轨选中、无单选圆点 | 最长文案换行与 360px 高度 |
| 图像题 | `docs/design/v2/concepts/quiz-visual-v1.webp` | 同尺度轴测图、对象差异先于文字 | 六张正式图像题的语义可读性 |
| 结果首屏 | `docs/design/v2/concepts/result-root-v2.webp` | 超大代码、人物建筑全幅图、紧凑元信息与证据入口 | Owner／Shared 状态、真实图像裁切 |
| 分享卡 | `docs/design/v2/concepts/share-root-v2.webp` | 4:5 卡面、身份优先、人物和主建筑、测试入口 | 1080 × 1350 Canvas 与聊天缩略图 |
| 建筑编辑长页 | `docs/design/v2/concepts/result-editorial-v1.webp` | 故事先于来源、一座主建筑先讲透 | 长文行长、真人肖像和来源折叠 |

```css
--paper: #f2efe7;
--paper-deep: #e7e1d5;
--ink: #121313;
--muted: #66645f;
--line: #bbb6aa;
--brand: #245aa6;

```

- 每个结果页只允许一个人格强调色，主色表继续由 `ResultType.accent` 驱动
- 默认界面不使用渐变；只有人物原画内部允许受控色彩变化
- 大面积底色保持暖纸白和近黑，蓝色只承担品牌、选择和可操作语义
- 纯装饰色块总面积必须受控，不让页面变成彩色卡片集合

#### V2.11.4 字体与文字层级

- 拉丁字母和数字使用一套可随项目本地加载的窄体无衬线，优先候选 `Barlow Condensed`；若最终体积或授权不合格，使用明确测试过的窄体回退，不依赖移动端不稳定的 `Arial Narrow`

- 最大标题使用 `clamp()`，按 360、390、430 三档检查真实换行
- 所有 UI 独立文案执行 V2.7 的句末标点规范

#### V2.11.5 网格、密度与媒体

| 项目 | 规则 |
|---|---|
| 主设计视口 | 390 × 844，兼容 360–430 主矩阵，320 为极限无横向滚动兜底 |
| 文本边距 | 18px；430 宽可增至 22px |
| 媒体边距 | 人格与建筑主视觉允许脱离文本边距全幅铺开 |
| 桌面主栏 | 测试不超过 520px；结果阅读区不超过 720px，不另造桌面信息架构 |
| 间距单位 | 4px；常用 8、12、16、24、32，不使用随意的 37／53px |
| 圆角 | 0、2、4px 为主；仅系统分享遮罩和必要浮层可到 8px |
| 边界 | 1px 实线、色块和排版层级，避免每个模块独立描边 |
| 阴影 | 页面容器无阴影；只允许人物落地或分享浮层使用有语义的轻阴影 |
| 高度 | 先 `100vh` 回退，再 `100svh`，最后 `100dvh`；处理上下安全区 |
| 触控 | 主要交互最小 44 × 44 CSS px，不依赖 hover |

媒体裁切必须按使用场景出图：

- 结果首屏人物图使用横向或已验证焦点的场景图；首页不加载人物图
- 分享卡使用专属 4:5 构图或从安全的 6:5 主图按已验收焦点裁切
- 建筑资料照片保留真实摄影，不与人格演绎插画混为一谈
- 所有媒体提前声明宽高，避免 CLS
- 人格首屏单图建议不超过 200 KB，任意单图不得超过 300 KB

#### V2.11.6 组件表达规则

- 首页：纯文字首屏包含品牌、超大标题、单句价值说明、开始／继续按钮和 `18 题 · 约 3 分钟 · 不用登录`；禁止人物预览、方法论、人格解释和装饰卡片
- 测试：去掉完整全站 Header，只保留流程微标、返回和唯一进度；选项整行可点，选中用左轨、底色和字重三重反馈
- 图像题：三张图必须同尺度、同相机、同精度，文字只辅助命名，不承担补救图像的任务
- 最后一题：选择后出现显式提交按钮；导航超过约 1.5–2 秒未完成时无条件显示可点击备用链接
- 结果首屏：人格代码、中文名、台词和场景成为一个构图；不显示“原创人格主视觉”“成人低多边形卡通”等制作术语
- 证据：每条同时包含 `你选了`、本人选项和 `这暴露了` 的解释
- 建筑师：先给“为什么同频”和一个故事，再在次级层级给生卒年、署名和来源
- 建筑：建筑师与作品不得拆成编号章节；前三座作品均用大图、Hook、三个看点和短故事展开，随后用两个小窗继续推荐
- 分享卡：只表达主人格、台词、人物、代表建筑师或主建筑、测试入口和二维码；不放相邻人格与原始答案
- About：来源按人格／建筑师折叠，末尾必须有开始测试动作

#### V2.11.7 明确禁止的模板化做法

- 玻璃拟态、发光渐变、大量阴影、悬浮 SaaS 卡片
- 大量胶囊标签、无意义圆形图标、装饰性汉堡菜单
- 用巨大空白替代版式层级
- 所有区块都套相同圆角卡片
- 用图像内生成文字充当真实 UI
- 只在桌面大图上验收、再让 CSS 强行适配手机
- 为追求“统一”把八个人做成同一姿势换颜色

### V2.12 人格角色与建筑场景的 V2 生产规则

#### V2.12.1 统一什么，变化什么

统一项：

- 明确成人形象，约 1:5.5–1:6.5 头身，不幼态化
- 受控的低多边形编辑插画人物，脸、手和衣褶有共同形体逻辑
- 同一相机与光线世界：近距离建筑环境、柔和自然光、清楚轮廓
- 建筑使用较大、较干净的几何面，碎面程度低于人物
- 画面无文字、Logo、UI、边框和水印

变化项：

- 人物可以是近景、全身、退到边缘或动作越出版心
- 表情覆盖温和、安静、固执、嫌弃、兴奋、戏剧和近乎癫狂
- 每人通过一个动作、一个道具和一处色彩强调表达性格
- 建筑构图跟随性格：严格轴线、材料触摸、沉重体量、光边、系统部件、连续曲面、细节扩散、手工材料

## 1. 产品定义

### 1.1 一句话介绍

`[已确认]`

> AIBTI 是一个通过 18 道潜意识、日常人格和建筑审美题，把用户匹配到一种建筑人格、建筑学派、建筑师与代表建筑的手机网页测试。

### 1.2 用户获得什么

`[已确认]`

- 情绪价值：得到一个有戏、有梗、但不羞辱人的人格角色；
- 社交谈资：用主类型、专属台词和分享卡与朋友比较；
- 自我表达：说清楚自己偏爱的空间、材料、秩序和情绪；
- 建筑知识：认识一种学派、一位核心建筑师和三栋代表建筑；
- 继续探索：从“如何看懂”与有来源的故事继续阅读。

### 1.3 产品核心承诺

`[已确认]`

> 三分钟找到你的建筑人格，再从代表建筑师和真实作品看懂自己的空间偏好

### 1.4 产品边界

`[已确认]`

- 它是娱乐与文化传播产品，不是临床心理测评。
- 它给出“偏好与人格共振”，不宣称用户与历史建筑师完全相同。
- 它解释建筑风格，不评判哪一种品味更高级。
- 人物形象可以戏剧化，但不能把真实人物的疾病、创伤或争议当成无依据的笑料。

### 5.1 题目组成

### 5.2 出题原则

`[已确认/建议]`

- 每道题能在几秒内理解和选择。
- 题干尽量短，选项优先是情景、动作或直觉。
- “玄乎”来自联想和画面感，不来自难懂词汇。
- 搞怪选项不能变成明显的正确答案提示。
- 不直接问“你喜欢哪种建筑主义”。
- 不要求普通用户认识建筑师或专业术语。
- 审美题使用项目自制抽象图，避免用户通过认识具体建筑猜结果；结果科普区可使用专业建筑网站搜集的真实建筑摄影。
- 每道题必须有明确测量目的，不能只为段子存在。

### 5.3 正式测量维度

`[已确认]`

所有维度都归一化到 -1 至 +1。负极与正极都不是优劣判断。

## 12. UI / UX 框架

### 12.1 体验原则

`[已确认]`

- 手机单手可完成；
- 每屏只完成一件事；
- 答题反馈快；
- 不使用建筑专业术语考用户；
- 视觉有建筑感，但不是建筑事务所官网；
- 结果首屏先给情绪冲击，再展开知识；
- 整体调性扁平、克制、紧凑，避免悬浮面板感和过度装饰；
- 内容密度高于常见营销落地页，不用大面积空白把相关内容拆散；
- 高密度不等于拥挤：通过字号、字重、分隔线、缩进和留白层级组织信息，而不是给每段内容套卡片；
- 页面保持简洁，避免堆叠大量小框、胶囊标签和重复容器；
- 人物和代表建筑承担主要视觉表现，UI 控件主动退后；
- 所有关键流程首先按微信内置浏览器中的手机竖屏场景设计，再验证其他现代浏览器。

### 12.2 设计治理与参考网页

`[已确认]`

本章就是项目的设计系统口径，不额外创建一份与本 PRD 平行的 `DESIGN.md`。

视觉决策优先级：

1. 用户已经确认的产品与视觉要求；
2. 本 PRD 的产品、内容和 UI 规则；
3. 已确认的人物视觉母版与后续批准的界面稿；
4. 项目内已经落地的设计变量和组件；
5. `frontend-design` Skill 的质量检查建议；
6. 外部参考网页中可借鉴的局部模式。

当前本地可用的 `frontend-design` Skill（其清单声明的 upstream 为 `anthropics/skills`）在本项目中只定位为“软性质量门”，不是主题、模板或组件库。`nexu-io/open-design` 与 `thesysdev/openui` 可作为范式研究来源，但不作为运行时依赖，也不直接控制项目 UI；若未来确需安装其中某一套规则，必须先审阅其技能说明并把被采用的规则写回本章。

允许它做：

- 在动手前帮助明确本产品自己的视觉命题；
- 检查字体、色彩、间距、层级、响应式和交互状态是否一致；
- 识别通用 AI 网页感、无意义装饰、卡片滥用和移动端问题；
- 对已经确定的页面提出可审查的改进建议；
- 在实现后参与浏览器视觉检查。

禁止它做：

- 覆盖本 PRD 或已确认视觉母版；
- 自动套用固定色板、固定字体、固定组件或固定页面结构；
- 因示例提示而把产品做成 SaaS Dashboard；
- 未经产品理由增加渐变、玻璃拟态、胶囊标签、装饰图标或大量卡片；
- 为了“显得高级”牺牲答题速度、可读性或人物辨识度；
- 另建一套设计规则，造成双重口径。

参考网页只作为交互和版式灵感，不建立竞品分析章节，也不复制其品牌、角色或具体美术：

| 参考网页 | 主要参考 | 本项目如何转译 | 明确不复制 |

| [SBTI](https://www.sbti.bio/zh/) | 轻量进入、连续答题、人格结果的传播节奏 | 保持测试入口直接、题面简洁、结果先给人格记忆点 | 品牌命名、角色造型、配色、卡面版式和原文案 |

## 13. 计分与结果参数

### 13.1 算法目标

`[已确认]`

算法需要做到：

- 同一套答案稳定产生同一结果；
- 题目能够解释结果，而不是黑箱随机；
- 人格题与审美题都真正影响匹配；
- 分数相近时有合理处理；
- 调整权重后可追踪版本。

### 13.2 正式计分流程

`[V2 已校准，scoringVersion: 2.0.0]`

```text
用户答案
   ↓
题目选项权重
   ↓
维度得分
   ↓
标准化
   ↓
与各结果原型比较
   ↓
主结果 / 副结果 / 置信度
```

具体规则：

1. 每个选项保存一个稀疏的 8 维权重向量，单项值范围 -1 至 +1。
2. 投射、人格、审美三组总权重分别为 0.30、0.35、0.35；组内 6 题等权，避免最难理解的图像题天然拥有最高权重
3. 每个维度分别累计 `optionWeight × groupWeight / 6`。
4. 每个维度再除以该维度在整套题中的理论最大绝对贡献，归一化到 -1 至 +1。
5. 用户向量与 8 个人格原型使用余弦相似度比较。
6. 分数最高者为主类型，第二高为副类型；完全同分时使用固定类型顺序保证结果可复现。
7. 不设置单题否决项，避免一道玩笑题决定全部结果。
8. 证据题为“该题所选向量与主类型原型点积贡献”最高的 3 题，只用于解释，不重新影响计分。

### 13.3 结果清晰度

设主类型与副类型的相似度差为 `gap`：

| gap | 标签 | 结果文案 |
|---:|---|---|
| `>= 0.16` | 清晰 | 你的建筑偏好相当坚定 |
| `0.08—0.159` | 平衡 | 主类型明确，但有可见侧翼 |
| `< 0.08` | 混合 | 两种人格正在你体内共同施工 |

数值置信度使用 `clamp(gap / 0.24, 0, 1)`。它只表达两个候选之间的距离，不宣称统计学置信度。

### 13.4 内部答案传输与公开结果 URL

`[V2 已改写；本节替代 v1 带答案结果链接规则]`

- 每题 3 个选项继续使用 2 bit 表示，18 题共 36 bit，编码为 Base64URL 字符串
- 答案码只允许短暂存在于测试页到计算页的 URL fragment：`/calculating/#a={answerCode}&u=3&q=2.0.0&s=2.0.0`；fragment 不进入 GitHub Pages／CDN 的 HTTP 请求目标或访问日志
- 计算页必须同时校验传输、题库和算法版本；V1 或未知版本不得用 V2 题序重新解释
- 计算完成后写入 `aibti.result.v2`，并使用 `replace` 进入不含答案的 Owner URL：`/result/root/?mine=1`
- 复制链接、系统分享和分享卡二维码只生成 `/result/root/?from=share` 或 `?from=card`
- 中性人格资料页为 `/result/root/`
- 公开结果 URL 永远不包含 `a`、`q`、`s` 或 `u`
- 答案不上传服务器；个性化证据只在完成测试的本机保存

### 13.5 算法版本

`[已确认]`

当前四类发布版本均为 `2.0.0`，所有本机结果保存：

- `quizVersion`
- `scoringVersion`
- `contentVersion`
- `artVersion`

任何题目权重或人格原型变化，都至少更新 `scoringVersion`。

```ts
type QuizSession = {
```

### 15.10 HarmonyOS 百度浏览器末题兼容修复

`[已实现；自动验证通过，待原设备复测]`

- 现象：HarmonyOS 的百度浏览器完成第 18 题后可能停留在答题页，用户侧表现为“点击没有效果”；
- 原因边界：前 17 题只更新本地状态，末题首次执行全量答案编码与 Next.js 客户端路由；原实现没有校验恢复进度的完整性，也没有处理存储、编码或 WebView History API 跳转失败；
- 会话修复：读取 `localStorage` 时逐题过滤非法/旧答案，并将不一致的进度修复到最早未答题；存储和清除异常不再抛出到答题事件；
- 导航修复：测试页到计算页、计算页到结果页均使用带 `/AIBTI/` 的完整页面导航，不再依赖末题的 History API 软路由；
- 用户兜底：末题点击后立即显示“正在生成结果…”，禁用重复操作；如宿主阻止程序化跳转，页面显示可直接点击的计算页或结果页链接；
- 可靠性修复：埋点事件异常不得阻断业务；末题发现缺题时明确提示并跳回最早未答题；
- 自动验证：52 项单元测试覆盖版本化会话、双存储最新记录选择、非法旧状态、fragment 计算转交、硬导航 watchdog、结果视图与公开路径；Playwright 在 HarmonyOS User-Agent 代理完成 18 题、显式提交、计算和 Owner 结果链路
- 证据边界：HarmonyOS 自动项目不是百度浏览器或系统浏览器真机认证，原问题设备仍必须用 V2 公网候选地址复测
- 兼容策略：不通过 UA 嗅探单独维护“百度浏览器分支”；硬导航和数据修复对微信、夸克、旧 Android WebView 与其他嵌入式浏览器同样生效。
